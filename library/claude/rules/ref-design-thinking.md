# Design Thinking

A human-centered problem-solving methodology. Five phases, non-linear — loop back when you learn something that changes your understanding.

## The Five Phases

### 1. Empathize
Understand the people you're designing for. Observe, engage, immerse.

**Methods**: user interviews, contextual inquiry, shadowing, diary studies
**Deliverables**: empathy maps, observation notes, quotes, behavioral patterns
**Key question**: "What does the user actually do, think, and feel?" (not what they say they do)

### 2. Define
Synthesize empathy findings into a clear problem statement.

**Methods**: affinity mapping, point-of-view statements, How-Might-We questions
**Deliverables**: problem statement, HMW questions, design principles
**Key question**: "What is the real problem?" (not the first problem stated)

**How-Might-We (HMW) framing**: Turn problems into opportunities. "Users abandon checkout" becomes "HMW make checkout feel effortless?"

### 3. Ideate
Generate a broad set of solutions. Quantity over quality at this stage.

**Methods**: brainstorming, crazy 8s, SCAMPER, mind mapping
**Deliverables**: idea backlog, ranked concepts, sketches
**Key question**: "What are ALL the ways we could solve this?" (defer judgment)

### 4. Prototype
Build quick, low-fidelity representations to test ideas. Speed matters more than polish.

**Methods**: paper prototypes, wireframes, clickable mockups, wizard-of-oz
**Deliverables**: testable prototypes, test scripts
**Key question**: "What is the cheapest way to test this assumption?"

### 5. Test
Put prototypes in front of real users. Learn, iterate, refine.

**Methods**: usability testing, A/B testing, feedback sessions
**Deliverables**: test findings, iteration plan, validated/invalidated assumptions
**Key question**: "What did we get wrong?" (design for learning, not validation)

## When to Loop Back

- Testing reveals the problem was misunderstood → go back to Empathize
- Prototype testing shows the solution direction is wrong → go back to Ideate
- New user insights emerge during testing → update the Define statement

## Common Anti-Patterns

- **Skipping Empathize**: jumping to solutions without understanding users. The most common and most expensive mistake.
- **Falling in love with the first idea**: not exploring alternatives before committing
- **High-fidelity prototypes too early**: spending weeks on polish before validating the concept
- **Testing for confirmation**: seeking validation instead of learning. Ask "what's confusing?" not "do you like it?"
- **Design thinking as theater**: going through the motions without actually changing decisions based on findings
